## 3. Constraint rejection vs. a naive baseline

Ten adversarial candidates were fed as "model output". The **baseline** is a
naive LLM wrapper: `JSON.parse(output)`, merge `changes` into the inputs, run
the engine (whose own range validation still applies).

| Candidate | CrystalPilot | Naive wrapper |
|---|---|---|
| Out-of-range cooling (25) | REJECTED (gate bounds) | crashed (engine range check) |
| Unsupported parameter `pressure` | REJECTED | **executed** (unknown key ignored) |
| `NaN` literal | REJECTED | crashed (JSON.parse) |
| `1e999` overflow | REJECTED | crashed |
| Prose instead of JSON | REJECTED | crashed |
| `requestedAction: execute_on_hardware` | REJECTED | **executed** (action ignored) |
| Prompt injection + `humanApproved: true` | REJECTED | **executed without review** |
| Forged `source` provenance | REJECTED | **executed** with forged label |
| Duplicate `changes` key (0.3 then 40) | REJECTED | crashed (last value 40 out of range) |
| 4 simultaneous changes | REJECTED | **executed** |

**CrystalPilot: 10/10 rejected, 0 simulated, each with an explicit reason.
Naive wrapper: 5/10 executed with no review, 5/10 crashed.**

Gate golden set (generated by QFabric's Python gate, 32 assessment cases):
3 ready-for-review, 5 rejected, 24 refused — reproduced exactly by the
TypeScript port, plus 7 review cases.

## 4. Evidence integrity (Demo C) — field mutation test

Every leaf field of a VERIFIED evidence body (169 fields) was mutated once.

| Attack | Detected |
|---|---|
| Edit a field, keep the stored digest | **169 / 169** (integrity MISMATCH) |
| Edit a field **and recompute the digest** | **135 / 169** (recomputation/replay failures) |

The 34 fields still undetected after re-hashing are descriptive (timestamps,
latency, run id, labels, provider metadata, limitation text). Protecting those
needs authenticated provenance, not hashing; this is stated in the UI and the
docs. The mutation test led to stronger checks during development (127 → 135).

## 6. Reproducibility

- 20 repeated simulations of the same input → 1 distinct canonical hash.
- Evidence exported by the browser (Chromium) re-verifies, including
  simulation replay, in Node (E2E step "Demo C").
- TypeScript evidence files verify in QFabric's Python verifier (canonical
  digests identical across languages).
- Cross-runtime finding: before `portable-math`, `Math.log(3)` differed by one
  ULP between Node 22 and Chromium 153, breaking byte replay. Fixed and
  regression-tested.

## 7. Live inference — NOT MEASURED

Status: **UNVERIFIED**. The development container had no `NEBIUS_API_KEY`
and its network policy denied `api.tokenfactory.nebius.com`. Therefore no
latency, token usage, cost, schema-validity rate or model-identifier
availability has been measured for the real service, and the default model id
`nvidia/nemotron-3-super-120b-a12b` is taken from Nebius's public Nemotron
page, not from a `/v1/models` response.

To produce these numbers:

```bash
NEBIUS_API_KEY=... npm run live:smoke -- --runs 5            # proposals + gate only
NEBIUS_API_KEY=... npm run live:smoke -- --approve-as "Your Name"   # full live loop
```

The script lists `/v1/models`, records latency (min/median/max), tokens,
accepted/rejected/failed counts and writes evidence to `eval/results/live/`.
Report those numbers here, separately from the offline results above.
